# Overlay 和流式接口验证流程

## 输入契约

先写清器件、PYNQ 和工具版本，bit/hwh 是否同一次构建；输入输出 dtype、长度、端序、通道排列、量化比例、TLAST/SOF、DMA 方向和寄存器偏移。不得将同名 IP 视为相同寄存器接口。

## 最小验证

1. 计算 bit/hwh SHA-256，检查 HWH IP 名称、地址范围、中断控制器和层次驱动。
2. 必要驱动在创建 Overlay 前导入，重新下载后重新创建所有依赖对象。
3. 先用零、脉冲和整 bin 正弦验证数值与包长，再使用应用数据。零输入只验证数据通路，不代表正常设备状态。
4. 使用硬件读回验证运行参数。FIR 系数设置后逐字读取比对；视频需确认像素格式、解包模式、颜色矩阵和 DMA stride。
5. 接收缓冲先挂接、再发送。应用帧和数组由真实接口契约确定，超时后记录状态并退出，不无限等待。
6. DMA 缓存管理采用该 PYNQ 版本驱动契约，读回输出前完成同步；不能同时使用由 VDMA 接管的帧内存。
7. PS 黄金参考采用相同数据、FIR 初始状态和特征定义。整数截位误差、FFT 累积误差和浮点误差分别说明。

## 性能与稳定性

算法处理时延、驱动端到端时延、数据收集时间、HDMI 页面更新时间分别计量。记录预热、输入、重复次数、CPU 竞争、原始逐次时延。持续输入时记录队列积压、丢帧和截止期，而非仅报告短时峰值。
